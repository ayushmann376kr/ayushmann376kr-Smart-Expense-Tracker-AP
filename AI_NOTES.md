## What was validated

The sandbox this was built in had no internet access, which forced a
concrete choice: FastAPI (the assignment's suggested first option) wasn't
installable, so the build used Flask, which was already present, and
Python's built-in `unittest` instead of `pytest` — both to avoid a
dependency that couldn't be verified as installable, and because it means
the test suite runs with zero extra packages beyond Flask itself.

Concretely verified, not just assumed correct:
- Ran `python3 -m unittest discover -s tests -v` — all 23 tests pass.
- Started the actual server (`python3 -m src.app`) and hit every endpoint
  with real `curl` requests (add x2, list, filter by category, total,
  total-by-category, and an invalid-input case), confirming the HTTP
  responses match what the tests assert.
- Checked the specific routing edge case of `/expenses/total` vs.
  `/expenses/<id>` — Flask/Werkzeug prefers the static rule, confirmed by
  the `curl` run above returning the totals payload rather than a 404.
- Confirmed data persists to `expenses.json` and is readable by a second
  `create_app()` instance pointed at the same file (`test_persists_to_file_across_app_instances`).

**What you should still do before submitting:** run the install/run/test

## AI suggestions not used / would reconsider

- **Client-supplied IDs.** The assignment lists `id` as one of the
  expense fields, which could be read as "the client provides it."
  Server-generated UUIDs were used instead, to avoid collision/overwrite
  bugs — but this is a judgment call worth revisiting if the grader
  expects client-supplied IDs.
- **pytest over unittest.** pytest wasn't installable in the build
  sandbox (no network), so `unittest` was used instead. If your machine
  has internet, you may prefer to port `tests/test_app.py` to pytest for
  nicer fixtures/output — the test logic itself doesn't need to change.
- **In-memory-only storage.** The assignment allows either in-memory or a
  local JSON file. JSON-file persistence was chosen over pure in-memory
  so data survives a restart, at the cost of a bit more I/O per request.
  For this assignment's scale that trade-off seemed worth it, but a
  pure in-memory dict would also have been a reasonable, simpler choice.
